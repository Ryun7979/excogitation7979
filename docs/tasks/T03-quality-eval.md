# T03 問題の質を確かめる評価の仕組み

- 優先度: 高
- 状態: ⏸ 仕組みは完了・教材画像待ち

## 背景

直近20件ほどのコミットは、ほとんどが「〜な問題を防ぐ」プロンプトの手直し。
直すたびに、前に直した問題がぶり返していないかを人の目で確かめている。

## やること

- 代表的な教材画像を `eval/images/` に置く（10〜20枚。漢字・計算・英語・理科・社会をまんべんなく）。**画像はユーザーが用意する。**
- モード（すなお・あまの・クイズ）×モデルごとにクイズを作るスクリプト `scripts/eval-quiz.ts` を作る。
- できた問題を、別のAIに観点ごとに採点させる。
  - 正解が1つに決まるか／正解がほんとうに正しいか
  - 教材を見ないと解けない問題でないか（「画像の」「ドリル」など）
  - 選択肢の誤字・同じ意味の選択肢がないか
  - 不自然な日本語・言い過ぎがないか
  - あまの先生: 丸写しになっていないか
- 結果を `eval/results/日付.md`（表）と JSON に残し、前回と比べられるようにする。

## 完了条件

- `npm run eval` で採点表ができる。
- プロンプトを変えた前後で数字を比べられる。

## 経過

### 2026-11-21

- [scripts/eval-quiz.ts](../../scripts/eval-quiz.ts) と `npm run eval` を作った。使い方は [eval/README.md](../../eval/README.md)。
  - アプリと同じプロンプト（[services/quizPrompts.ts](../../services/quizPrompts.ts)）と同じ検証（quizValidation）を使う。
  - モデル×モードごとに、かかった秒数・使える問題の数（12問中）・捨てた理由の内訳・採点の合格率を表にする。
  - 採点の観点: 正解が正しい／正解が1つ／教材を見なくても解ける／誤字がない／自然な日本語で言い過ぎがない／（あまの先生）丸写しでない。
  - 結果は `eval/results/日時.md` と `.json` に残す。
- `eval/images/` は著作物・個人の持ち物なので git に入れない（`.gitignore` に追加）。
- 試しに、PowerShell で描いたテスト画像2まい（漢字ドリル・計算ドリル風）で、gemini-3.5-flash-lite × あまの先生を1回まわした。
  - 結果: 8.8秒、12問中12問使える、すべての観点に合格したのは 90%。
  - 不合格の例:「『海』という漢字を使っていて、船が出入りする場所を表す言葉は？（正解: 漁港）」。採点AIが「漁港に『海』は入っていない」と指摘した。
  - **このような「条件と正解が合わない」問題は、今のコードの検証では見つけられない**ことが分かった。
- アプリで遊んだときの気づき（すなお先生・写真3まい）: 10問中5問が「漢字『○』の読み方として正しいものは？」という同じ型だった。評価で「同じ型の問題の割合」も見られるとよい。
- 残り: 代表的な教材の写真（10〜20まい）を `eval/images/` に置き、すべてのモデル×モードで1回まわして、基準になる結果を残す。
