# T06 待ち時間を短く感じさせる

- 優先度: 中
- 状態: ✅ 完了（残りは [引継ぎ資料](../handover.md) にまとめた）

## 背景

12問がそろうまで生成中の画面で待たせている。混雑時は1分以上かかる。

## やること（案）

- 案1: 生成中の画面に、何をしているか（解析中→問題づくり中）と、経過時間・目安を出す。豆知識や操作説明を出して待ち時間を埋める。
- 案2: ストリーミングで受け取り、最初の数問ができた時点で遊び始める。
  - ただし今は「12問作って検証を通った10問を使う」ので、途中で始めると後半の問題が足りなくなったときの扱いが難しい。案1を先にやり、案2は効果と手間を見て判断する。

## 完了条件

- 生成中に、いま何をしていて、どのくらい待てばよいかが分かる。

## 経過

### 2026-11-21

- 案1を実施した（[screens/GeneratingScreen.tsx](../../screens/GeneratingScreen.tsx)）。
  - いまの段階（解析中／問題を作成中／枚数を減らして再挑戦中 など）を大きく表示する。
  - 「○まいの写真から問題を作っているよ（○秒）」と経過秒数、目安を出す。目安は、ふつうは30秒くらい → 30秒をこえたら「もう少しまってね」→ 60秒をこえたら「AIがこみあっているみたい」。
  - 7秒ごとに変わる遊び方のヒント（キーボードで答えられる、ランプでやり直せる、きろく など）。
- 実測: 写真3まいで、問題ができるまで約20秒だった。
- 案2（ストリーミングで途中から遊び始める）は保留。今は12問作って検証を通った10問を使うので、途中で始めると後半が足りなくなったときの扱いが難しい。T03 の評価で「捨てる問題の数」が少ないと分かれば検討する。
