# T12 条件と正解が合わない問題・同じ型の問題を減らす

- 優先度: 高
- 状態: 🔄 作業中

## 背景

T03 の評価とアプリで遊んだときに、次の2つが見つかった。

1. **条件と正解が合わない問題**
   - 例:「『海』という漢字を使っていて、船が出入りする場所を表す言葉は？（正解: 漁港）」。漁港に『海』は入っていない。
   - 今の [services/quizValidation.ts](../../services/quizValidation.ts) では見つけられない。
2. **同じ型の問題が多い**
   - 例: すなお先生・写真3まいで、10問中5問が「漢字『○』の読み方として正しいものは？」だった。

## やること

- プロンプト（[services/quizPrompts.ts](../../services/quizPrompts.ts)）で、
  - 問題文の条件（「『X』を使った」「答えが N になる」など）を、正解が本当に満たしているかを確かめさせる。
  - 同じ問い方が続かないよう、問い方の種類と上限を決める。
- コードで確実に見つけられるものは [services/quizValidation.ts](../../services/quizValidation.ts) で捨てる（テストも書く）。
  - 「『X』を使った言葉は？」型で、正解に X が入っていない。
  - 計算の答えが合わない（「36 − 19 はいくつ？」の正解が 17 でない、「答えが 20 になる式」の正解が 20 にならない・20 になる不正解がある）。
- 同じ型の問題が多いときは、予備の問題（12問作って10問使う）から別の型を優先して選ぶ。
- 誤判定で正しい問題を捨てすぎない（捨てすぎると作り直しが増え、待ち時間が延びる）。
- 評価（`npm run eval`）に「いちばん多い型の割合」を足し、変更前と変更後を比べる。

## 完了条件

- 上の2つの例のような問題が、プロンプトとコードの検証で減っている（評価の数字で確かめる）。
- `npm test`・`npx tsc --noEmit`・`npm run build` が通る。

## 経過

### 2026-11-21

**何をしたか**

- コードの検証（[services/quizValidation.ts](../../services/quizValidation.ts)）に足したもの。`sanitizeQuestions` で捨てる・選ぶ。
  - `violatesKanjiCondition`: 「『X』を使った／が入る／のつく言葉は？」型で、正解に X が入っていなければ捨てる。誤判定を減らすため、否定の問い（「使わない」「〜ではない」）、読み・意味・部首・画数を問う問題、正解が漢字を含む短い言葉でない問題は見ない。
  - `violatesArithmetic`: 「36 − 19 はいくつ？」のように式だけを計算させる問題で正解の数が合わない、または「答えが 20 になる式は？」で正解が 20 にならない・不正解にも 20 になる式がある問題を捨てる。文章題・□を求める問題・単位つきの答えは見ない。式は自前の小さな計算器で計算する（`eval` は使わない）。
  - `questionKind` と `pickVaried`: 問い方を「読み・書き・意味・英語・計算・その他」に分ける。検証を通った問題が10問より多いときは、同じ型を4問まで（10問 × 0.4）にして、ほかの型を先に選ぶ。足りないぶんは残りから補うので、問題の数は減らない（計算ドリルで全部が計算でも、そのまま10問になる）。
- テストを11件足した（合計98件、すべて成功）。
- プロンプト（[services/quizPrompts.ts](../../services/quizPrompts.ts)）:
  - `asks` に問題文の条件（『海』を使う・答えが20 など）をすべて書き出させ、`solution` で正解の候補が条件を満たすかを確かめさせる。
  - 共通ルール 0b に「正解は問題文の条件をすべて満たす」を足し、漁港の例を悪い例として入れた。
  - 共通ルール 6【問い方を散らす】を足した: 同じ問い方は12問中4問まで、漢字なら読み・書き・送りがな・意味・熟語や使い方を組み合わせる。すなお先生の指示にも「読み方ばかりにしない」を足した。
  - 部首・画数・筆順は、教材にはっきり書いてあるときだけ問うようにした（下の評価で、部首の問題の正解がまちがっていたため）。
- 評価スクリプト（[scripts/eval-quiz.ts](../../scripts/eval-quiz.ts)）:
  - 「同じ型の最大割合」の列と「問い方の内訳」を足した。捨てた理由に `conditionMismatch` を足した。
  - 混雑（503・504）と回数制限（429）のときは待って再試行するようにした。1日の上限に当たったときはすぐにやめる。秒数は成功した1回だけを数える。

**わかったこと**

- 同じ型の問題は、すなお先生で 69% → 38〜42% に減った（10問中7問が読み → 4問ほど）。クイズモードはもともとスタイルを割り当てているので、ほぼ変わらない。
- 「すべて合格」は、すなお先生で下がった。ただし1回あたり16〜19問しかないので、ぶれが大きい。不合格の中身は次のとおり。
  - 問い方を散らした結果、軽いモデルが苦手な問題（部首: 「災」の部首を「川部」や「囗」とする）が出た。部首の指示を足したあとも、教材のページに部首の囲みがあるためか、1問出た。
  - 「魚市場」の読みを「うしいちば」とするなど、もとからある読みのまちがい。
  - 採点AIが「実在しない言葉」を誤字とみなした例が2つ（「校枝」「円囲」）。熟語の問題の不正解は、実在しない言葉にするようプロンプトで決めているので、これは採点のほうの問題。
- 条件と正解が合わない問題（漁港の型）は、コードで1問だけ捨てられた（変更後の2回目の評価）。変更前の評価で採点AIが見つけた不合格にも、この型はなかった。めったに出ないが、出たときは確実に捨てられる。誤判定で正しい問題を捨てたようすはない。
- ヒントを3つ出す問題で、ヒントが正解に当てはまらないものがあった（「ヒント1: 火の部首で炎を表す」→ 正解「災」）。これはコードでは見つけられない。
- 全34まいの評価（変更前）は、混雑で6回中2回しか作れなかった。いろいろな教科がまざっているので、同じ型の割合は 10〜20% と低かった。文末が「。」ではなく「.」になる問題が、すなお先生で5問あった。
- API キーは無料枠で、gemini-3.5-flash（採点）が1日20回の上限に当たった。そのため全34まいの変更後の評価と、あまの先生の評価はできなかった。

**残ったこと**

- すなお先生の「すべて合格」が下がったのが、問い方を散らしたせいなのか、ぶれなのかを確かめる（上限が戻ったら、同じ写真で `--repeat=3` 以上で回す）。下がっているなら、散らす型を「読み・書き・意味」にしぼる。
- 全34まい・あまの先生でも変更後の評価を回す。
- 採点の観点 `noTypos` に「熟語の問題で、わざと実在しない言葉にした不正解は除く」と書き足す。
- 文末の「.」を「。」に直す（コードでできる）。
- 評価の JSON に、捨てた問題の中身も残す（どの問題がなぜ捨てられたかを見られるように）。
